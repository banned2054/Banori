# qBittorrent 后续任务

整理日期：2026-10-27。对应 v0.2.2 发版准备，记录本版之后继续推进的工作。

本文件承接 [异步生命周期计划](QBITTORRENT_ASYNC_LIFECYCLE_PLAN.md) 中尚未完成的要求，区分已确认的实现差距与待核查、待验收项目。已落地的原下载设计和已完成的文件编号核实记录见 [归档目录](Archive/README.md)。原计划保留设计依据和历史实施记录；本清单不是全部设计条目的完整审计，也不将已有本地测试等同于真实环境验收。

## 本次已落地的范围

- 停止状态与完成程度独立判定，完整内容直接归档，恢复启动响应丢失的任务时先核对远端事实。
- 确认窗口、请求预算、下一次观察时间和路径决策持久化，重复 pulse 不绕过采样节奏或消耗补发预算。
- 校验轮次、长校验期限、稳定样本及中断恢复；未确认校验不登记复用成功，保护未证实的共享数据。
- 下载阶段、停止来源、路径原因、校验进度与内容进度及最后观察时间的展示，含已发现展示遗漏和 Unknown 调度回归的修复。

这些内容已有源码、模拟会话和本地数据库测试覆盖，真实环境验证仍见后文。

## 已确认的实现差距

### 1. 按原因选择重试与恢复动作

- [ ] 区分继续确认、重新发起校验、恢复布局与隔离恢复，明确每种原因允许保留或必须作废的证据、日志和预算。
- [ ] 为失败原因提供相应恢复入口，不统一通过放弃复用来恢复所有校验异常。
- [ ] 覆盖重启、响应丢失、预算耗尽后的人工重试，以及多次重试的幂等性。

当前行为：`DownloadService.RetryAsync` 对仍带校验意图的失败任务调用 `EnterIsolationAsync`，随后重新进入提交队列。原计划第三阶段已明确将原因分类的恢复入口延期。

验收：仍可继续确认的任务不产生多余 recheck、删除重加或独立下载；证据失效的任务不能沿用旧结果；人工暂停意图与共享数据保护始终有效。

### 2. 原始下载器状态与阶段诊断

- [ ] 在观察快照中保留诊断需要的原始 qB 状态，分别表达业务类别、移动属性和观察时间。
- [ ] 补齐阶段转换、轮次、进度、路径摘要、请求时间、确认期限、请求次数及退出原因的关联日志。
- [ ] 对未变化信息去重，避免高频采样产生重复日志；不记录凭据或带 passkey 的 tracker、RSS 地址。

当前行为：`TorrentSnapshot` 提供归类后的 `Category` 和 `IsMoving`，未保留原始状态；`LastObservedCategory` 也不能还原具体的排队、停止或校验状态。增加诊断信息时，不应仅为记录原始状态而改变既有业务分类。

验收：能够按任务与轮次还原请求和观察的先后关系，解释具体等待原因，同时保持敏感信息边界。

### 3. 异常快照的确认与恢复策略

- [ ] 区分暂时查不到种子、网络请求失败、持续缺失及下载器真实错误，明确各自的确认期限和退出条件。
- [ ] 核对 Error / MissingFiles 是否持续、是否与已有操作相关，再决定受阻或隔离；需要紧急保护共享数据时仍先停止。
- [ ] 覆盖正常观察后短暂缺失、错误恢复、持续错误、响应丢失与重启后的确认窗口，不伪造 0% 或错误登记复用成功。

当前行为：`AdvanceVerificationAsync` 对快照缺失的等待仅覆盖刚添加后的可见性窗口，窗口外直接进入隔离；观察到 Error 类别也直接进入隔离。网络异常另由对账捕获后重试，尚不能据此认为已经实现所有异常的独立期限和持续性确认。

验收：暂态异常不触发多余删除重加或重新下载，持续异常有明确的有界退出与恢复原因；确认等待不能放任未证实的共享写入。

## 待专项核查与补齐

### 4. 时钟变化与未来时间戳

- [ ] 核查系统时钟回拨、持久化时间戳异常及重启后时间变化对观察时间、确认窗口和校验期限的影响。
- [ ] 为异常未来时间戳确定恢复规则，并补充可步进时钟回归。

当前已使用 UTC 与 `TimeProvider`；本项尚未完成独立专项核查，不能仅凭这两点认定已经满足“不因未来时间戳长期等待”的设计要求。

验收：异常时间不会导致任务无限等待，也不会造成请求风暴、绕过确认窗口或误用旧校验证据。
