# Banori v0.3.0

本版本围绕来源隔离和下载可靠性进行了更新：不同来源的订阅候选与逐集版本分别竞争；下载复检、重启恢复和文件复用结果也有了更清晰的状态记录与展示。

项目和相关测试工程现已使用 .NET 11。

## 主要更新

- **按来源独立选择版本**：RSS 来源按订阅地址识别，上传来源按 tracker 分类。同一动画、同一集的不同来源不会互相淘汰；合集和单集候选按逐集规则进行比较。文件数据仍可跨来源复用。
- **订阅站点兼容**：订阅地址校验与来源识别共用站点映射，修复 `mikanime.tv` 可识别为蜜柑却无法创建订阅的问题。
- **上传来源标签统一**：未命中已知 tracker 分类的上传种子，默认来源由 `bt` 调整为 `other`；升级迁移会同步归一数据库中的历史任务来源。
- **更稳妥的下载复检与恢复**：记录复检请求及结果证据，区分“文件是否完整”和“下载或做种是否已恢复”。应用重启或请求响应未知时，先核对 qBittorrent 的实际状态；未确认的复检结果不会被当成成功或数据损坏。
- **更清楚的任务状态**：下载任务页展示当前阶段、等待原因和下一步；文件详情展示选择状态及复用校验结果。
- **测试基础设施更新**：升级测试 SDK 与 Visual Studio 测试适配器；E2E 场景在 gate 未启用时动态标记为跳过。
- **qBittorrent 客户端更新**：升级 `Banned.Qbittorrent` 到 `1.8.0`。
- **数据库驱动更新**：MySqlConnector 升级到 `2.6.2`，包含零配置 TLS 场景下的密码泄露修复。
- **出站请求标识**：默认 User-Agent 更新为 `Banori/0.3.0`，已有的顶层 `UserAgent` 自定义配置仍可覆盖默认值。
- **扩展验收与架构资料**：增加隔离的 qBittorrent 测试工具和跨站种子复用验收场景，并整理下载业务规则与架构文档。

## 升级注意事项

- 容器镜像和本地运行目标已切换到 .NET 11。镜像已包含 ASP.NET Core 11 运行时，宿主机无需另装 .NET；直接运行已发布的框架依赖产物需要 ASP.NET Core 11 Runtime，从源码构建或运行需要 .NET 11 SDK，单独安装 .NET Runtime 不足以运行 Web 应用。
- 本版为 SQLite 和 MySQL 新增数据库迁移，并在启动时回填可判定来源的历史记录。升级前请停止旧实例，备份数据库及配套 `config/`、`keys/`，并避免新旧版本同时写同一数据库。
- 来源无法确认或迁移遇到冲突的历史记录会保留在 `(legacy)` 作用域，不参与已知来源之间的竞争；详情写入启动日志。
- 未命中已知 tracker 分类的新上传任务会使用 `other` 作为 qBittorrent 来源标签及命名模板 `{source}`、`{site.source}` 的值。迁移会将历史任务的 `bt` 来源改为 `other`，并对非空任务来源去除首尾空白、转为小写；这不代表已有 qBittorrent 标签、命名快照或磁盘文件名会被批量改写。依赖旧来源标签或名称的外部规则应一并核对。
- 回退时请恢复升级前的数据库和配置备份。升级后可能已有同一集的多来源记录，直接反向迁移不保证成功。
- MySQL EF Core 提供程序目前使用 `11.0.0-preview.1`，因为尚无稳定版 11.x；真实 MySQL 实例迁移尚未验证，建议先在备份或预发环境验证。

## 当前边界

- 来源隔离针对订阅预选和版本竞争；上传入口仍按 info-hash 全局查重。未命中已知 tracker 的上传种子归入 `other`，目前没有可确认的 AniBT 上传 tracker 映射。
