## v0.6.0

本版本将下载任务页全面切换为无页码虚拟滚动列表并接入 qBittorrent `sync/maindata` 增量同步与文件自动对账，支持已完成任务外部换根重绑，并将种子名模板改为全局实时规则、修改后自动同步已有任务。

### ✨ 新增与改进

- **无页码虚拟滚动与前台自动同步**：下载任务页移除顶底页码，改为固定行高虚拟滚动列表，拆分有序任务 ID 快照与视口行摘要查询，支持按任务 ID 独立加载详情与跨滚动保留批量勾选（「全选本页」调整为「勾选可见行」）。引入数据库提交通知（`DownloadTaskChangeNotifier`）与前台 15 秒兜底刷新，打开或切回前台时立即同步。
- **qBittorrent `sync/maindata` `rid` 增量同步**：实现按下载器共享的 `sync/maindata` `rid` 增量协议与同步服务，前台以约 2 秒节奏增量拉取活跃任务进度、速度与状态并叠加到主表；支持首次全量、增量合并、移除处理、配置切换与断线重连自动回退全量。
- **文件自动同步、外部换根重绑与改名确认唤醒**：展开的文件列表支持打开或切换任务立即读取并每 5 秒自动同步（后台或收起时自动暂停，失败可自动恢复）；已完成任务在 qBittorrent 外部改名或换根后，两次核对保存根稳定且通过种子文件索引与字节数校验后自动重绑 `SavePath` 与文件路径。Banori 发起改名或移动后立即回读确认，未就绪时唤醒对账按约 1 秒间隔跟进确认。
- **种子名模板全局实时生效与已有任务分流同步**：普通种子名与合集种子名模板改为全局实时规则，不再依赖或回写任务命名快照中的旧模板字段；设置页修改保存后按单集与合集分流更新未删除且未丢失任务的目标名，并写入待改名标记（`TorrentRenamePending`），由后台对账异步推送至 qBittorrent。
- **下载任务右键菜单与首页反馈微调**：精简并美化下载任务右键菜单（移除重复的详情与文件页签入口，新增图标、分隔线与视口边界自适应定位）；总览页登记种子或一次性 RSS 成功时不再显示成功横幅，仅在失败时展示错误反馈。

### 🧪 测试与文档

- 新增下载任务列表与文件同步设计稿（[DOWNLOAD_LIST_AND_FILE_SYNC_DESIGN.md](DOWNLOAD_LIST_AND_FILE_SYNC_DESIGN.md)），并补充虚拟列表查询、数据库提交通知、前台自动同步、已完成任务外部换根重绑与改名确认、qB `sync/maindata` `rid` 增量同步及种子名模板变更同步等验收回归测试。
- 2026-11-24 在 .NET 11 下以 Release 配置复验，1435 项回归测试通过，0 失败、0 跳过；真机 E2E 验收场景本轮未运行。

### ⚠️ 升级说明与已知边界

- 本版为 SQLite 和 MySQL 新增数据库迁移（`AddTorrentRenamePending`，在 `DownloadTasks` 表新增默认值为 `false` 的 `TorrentRenamePending` 字段），启动时自动应用。升级前请停止旧实例并备份整个 `config/` 目录，MySQL 部署还须单独备份数据库，不要让新旧实例同时写入同一数据库。回退时恢复升级前的数据库和配套配置、密钥，不能只切换回旧镜像。
- 下载页虚拟滚动、`sync/maindata` 增量进度、外部换根重绑及种子名模板同步等链路已通过单元与验收回归覆盖，浏览器与真机 qBittorrent 场景尚待实测验证。发现异常请在 GitHub 反馈。

## v0.5.1

本补丁优化全局布局与导航体验，统一总览与下载任务页的上传种子和一次性 RSS 浮层，补充下载任务多列排序，并修复详情版本号展示语法。

### ✨ 新增与改进

- **界面布局与侧边栏导航**：顶栏展示当前页面标题并整合右上角用户菜单（个人资料、深浅色主题切换、退出/登录），各子页面移除重复标题区。桌面端左侧导航栏支持折叠与展开并在首屏渲染前恢复状态，避免宽度跳动；动画总览页排序改为紧凑浮层菜单，设置页择优规则在全部语言已添加时禁用语言选择与添加按钮。
- **统一上传种子与一次性 RSS 浮层**：抽取共享组件 `DownloadIntakeActions` 取代原 `DownloadForms` 与下载页内联上传卡片，在总览页与下载任务页顶部统一以浮层方式提供「上传种子」与「一次性 RSS」入口，进一步释放下载任务列表空间。
- **下载任务多列排序与列表微调**：下载任务主表支持点击动画、字幕组、语言、版本与发布时间列头排序（含多级回退与择优规则顺序）；进度条与百分比改为同行紧凑展示；单击任务行仅选中任务，不再自动展开/折叠底部详情面板。

### 🐛 修复

- **下载任务详情版本号展示**：修正 `DownloadTaskDetails.razor` 中版本号插值语法（`v@(Task.Version)`），修复版本号在详情面板中渲染异常的问题。

### 🧪 测试与文档

- 2026-11-23 在 .NET 11 下以 Release 配置复验，1398 项回归测试通过，0 失败、0 跳过；真机 E2E 验收场景本轮未运行。

### ⚠️ 升级说明与已知边界

- 界面布局调整、下载任务多列排序及浮层交互以代码变更与既有单元回归覆盖，尚待浏览器真机验收。发现异常请在 GitHub 反馈。

## v0.5.0

本版本重做下载任务页的信息布局，补齐文件改名的冷静期对账，并把设置页重组为分组标签。

### ✨ 新增与改进

- **qB 风格下载任务面板**：任务列表与详情面板上下分离，桌面端列表占满剩余视口并独立滚动、表头固定；分隔条可拖拽调整详情高度并记住上次高度。详情拆为「详细信息」与「文件列表」两个标签页，非异常态操作统一放在详情头部，错误提示与恢复入口集中到顶部 Alert。任务行右键改为「查看详细信息 / 查看文件列表」浮层菜单；详情在文件标签且展开时，15 秒轮询联动刷新文件清单。
- **列表列拆分与集数格式化**：主表由 4 列扩为 10 列（批量模式 11 列），动画名、字幕组、大小、进度、速度、剩时与发布日期各自成列；集数按逗号分段展示，单集与区间补 `E` 前缀，多段以首末集加 `*` 简写并在 Tooltip 与详情中保留完整区间；窄屏表格可横向滚动。
- **设置页分组标签**：设置页改为标签式导航，命名模板与媒体/种子目录从下载器卡片拆出为独立的「目录与命名」卡片，并加入种子名、合集名与文件路径的实时预览，便于在修改模板时确认效果。
- **择优规则并入设置**：择优规则从侧边栏独立页面迁入设置页的内嵌组件，卡片与规则列表统一样式并改为紧凑图标按钮；旧 `/selection-rules` 路由自动重定向到 `/settings/selection-rules`，侧边栏移除原入口。

### 🐛 修复

- **文件改名冷静期不再误报冲突**：应用改名后立即刷新文件时，后台等待 qBittorrent 确认待处理操作；保护期内禁用「刷新文件」「修改」与编辑区并给出醒目提示，确认后自动刷新一次路径并解锁，不再抛出「文件操作尚未确认」。
- **冷静期超时与轮询失败保持锁定**：等待超时或本地清单查询异常时只暂停自动等待，仍保持编辑锁定并提示「继续等待确认」；点击后安全恢复等待，只有清单确认无 pending 并完成一次刷新才解锁，页面释放时取消等待循环。
- **下载页 Review 问题**：工具栏移出裁切容器，列表与消息条补足最小高度；右键切换任务时联动文件标签，详情恢复回调统一走页面包装方法的取消令牌，详情默认收起；拖拽只更新本地 CSS 变量、不再回写存储，高度未变时不写盘；表头背景跟随主题，非批量模式任务行显示可点击光标。

### 🧪 测试与文档

- 新增下载页详情与文件面板渲染、文件清单自动刷新、冷静期确认后自动刷新与超时/轮询失败恢复、集数格式化、命名预览等回归，并更新相关测试替身与断言。2026-11-23 在 .NET 11 下以 Release 配置复验，1398 项回归测试通过，0 失败、0 跳过；真机 E2E 验收场景本轮未运行。
- 清理本地启动配置中无用的 `inspectUri`，不影响编译、发布与容器运行。

### ⚠️ 升级说明与已知边界

- 本版无数据库结构迁移；从 0.4.2 升级可直接替换程序，仍建议升级前停止旧实例并备份整个 `config/` 目录，MySQL 部署另需备份数据库，不要让新旧实例同时写入同一数据库。回退时恢复升级前的数据库和配套配置、密钥，不能只切换回旧镜像。
- 下载任务页新布局、设置页标签与命名预览尚待浏览器真机验收；qBittorrent 文件改名冷静期以单元回归覆盖，本轮未运行真机场景。发现异常请在 GitHub 反馈。

## v0.4.2

本补丁让文件名模板改为全局实时生效，并改进下载任务页的分页与单条操作入口。

### ✨ 新增与改进

- **文件名模板全局实时生效**：下载完成后视频、字幕文件的命名模板（`FileNamingTemplate`）改为按当前设置实时渲染，修改后立即对所有任务的预览、应用与归档改名生效，按各任务自身命名要素重新计算，不再把模板写回任务快照。新任务与订阅创建的命名要素不再保存 `FileTemplate`，设置页文案同步说明。种子名模板仍沿用创建时的快照，不在本版改动范围。
- **预览一致性与连带改名提示**：文件改名预览携带当时的模板指纹，应用前若当前模板已变化则拒绝应用并提示重新预览，避免预览与实际改名不一致；预览同时列出同种子其他已选文件因模板或布局变化会一并改名的当前路径与目标路径，编辑前即可看到影响范围。
- **下载任务页底部分页与右键菜单**：任务列表下方增加居中的分页条，仅在多页时显示；任务行支持单击选中高亮，右键选中的行弹出靠近鼠标位置的浮动操作菜单，点空白处或按 Esc 关闭。单条删除按钮从任务行移入该菜单，操作列的常规操作与菜单共用同一组按钮，避免两处状态判断走偏。批量选择模式保持原有复选框交互，不受单选影响。
- **下载按钮样式统一**：总览与下载任务页的「添加 Torrent 下载」「RSS 链接下载」「选择并上传 .torrent」统一为透明填充（outline）样式。

### 🐛 修复

- **在飞归档不因模板变化卡住**：待执行的归档按已持久化的目标日志收尾，不再用当前模板重算文件名；模板改动后仍按登记目标完成根移动，同时保留对人工路径覆盖被篡改的拒绝校验。全链路改为读当前模板，避免不回写后按旧快照重算与已登记计划冲突。

### 🧪 测试与文档

- 新增「应用不回写快照」「预览后改模板被拒」「连带改名提示」「模板变化后仍按登记日志完成归档」「在飞恢复按登记目标而非当前模板」等回归，更新相关接口替身与归档用例的模板断言。2026-11-22 在 .NET 11 下以 Release 配置复验，1367 项回归测试通过，0 失败、0 跳过；真机 E2E 验收场景本轮未运行。

### ⚠️ 升级说明与已知边界

- 本版无数据库结构迁移；从 0.4.1 升级可直接替换程序，仍建议升级前停止旧实例并备份整个 `config/` 目录，MySQL 部署另需备份数据库，不要让新旧实例同时写入同一数据库。命名模板改动只影响之后的预览与改名操作，不批量改写已有文件名或任务快照。
- 下载任务筛选与分页的 MySQL 查询翻译尚未完成真机验证；深色模式与右键菜单的浏览器验收待补；缺种巡检与受控重下、未决 Add 台账等链路仍以单元回归覆盖，尚未运行真机 qBittorrent 场景。发现异常请在 GitHub 反馈。

## v0.4.1

本补丁改进下载文件刷新与动画页排序体验，并修正无 Seed 复用校验任务落到全局下载根的问题。

### ✨ 新增与改进

- **动画页排序持久化**：动画总览页的排序字段与升降序写入应用设置 `Anime.Sort`，刷新或重新进入页面后恢复用户上次的选择；未保存过、内容无法解析或排序枚举值已移除时回退为名称升序。读取已保存排序期间用户切换排序时，以用户最新选择为准；连续切换按调用顺序串行保存，读取或保存失败只记录日志，当前页面仍按新排序显示。
- **文件刷新独立入口**：下载任务的「刷新文件」按钮改为显式刷新，实时查询下载器并按原始种子身份核对后同步路径，与展开文件面板时的清单加载分开；刷新成功后旧预览一并失效，避免继续引用刷新前的路径。

### 🐛 修复

- **刷新文件路径同步**：按分隔符归一化后以区分大小写的比较同步 qBittorrent 返回的文件名，大小写改名不再丢失；拒绝空白或非法相对路径（绝对路径、`:`、`..`、文件名首尾空白等）。读取清单前后各核对一次保存根与移动状态；原始种子 InfoHash、文件数量、index 映射与文件大小任一不一致即整批拒绝落库，已发布路径只在与当前路径一致时才随之更新。文件操作尚未确认、种子已删除或下载器目录中途变化时给出明确错误。
- **无 Seed 复用校验根**：无 Seed、非替换且只含正片的任务以媒体目录作为复用校验的添加根，与正式提交口径一致；此前校验根被拉回全局下载根，导致文件相对路径多出 `Media/Anime/` 前缀、校验路径偏离最终媒体目标。曾完成任务的重下仍使用任务专属暂存路径，替换判断沿用原有逻辑。

### 🧪 测试与文档

- 新增大小写改名、刷新中途换根、归档 Completed 外部改名等文件刷新回归，以及排序设置读取与写入竞态、无 Seed 校验根的路径断言。2026-11-22 在 .NET 11 下以 Release 配置复验，1361 项回归测试通过，0 失败、0 跳过；真机 E2E 验收场景本轮未运行。

### ⚠️ 升级说明与已知边界

- 本版无数据库结构迁移；从 0.4.0 升级可直接替换程序，仍建议升级前停止旧实例并备份整个 `config/` 目录，MySQL 部署另需备份数据库，不要让新旧实例同时写入同一数据库。动画排序偏好存放在既有应用设置存储中，不涉及新增表或列。
- 下载任务筛选与分页的 MySQL 查询翻译尚未完成真机验证；深色模式的浏览器验收待补；缺种巡检与受控重下、未决 Add 台账等链路仍以单元回归覆盖，尚未运行真机 qBittorrent 场景。发现异常请在 GitHub 反馈。

## v0.4.0

本版本围绕种子丢失与下载路径布局更新：缺种巡检自动发现种子被删除的旧任务并支持受控重下；下载提交与归档按新一轮布局解析路径，未确认的 Add 请求持续占用提交路径，避免结果未知时并发误写同一目标。

### ✨ 新增与改进

- **缺种巡检与受控重下**：任务按排期巡检，严格区分「查到」「成功查无」「查询未知」三种结果；首次查无留下待复核证据，第二次查无且下载器配置一致才确认缺失，查询未知不写任何字段。确认缺失的任务显示徽标并进入「丢失」分组（同时保留在「已完成」），页面提供重新下载入口：种子已回来时只清除标记，确认查无才建立新一轮受控重下，固化已发布布局并清除旧意图与缺种证据；同 hash 活动任务先明确拒绝。巡检配置指纹绑定连接地址、用户名、保存路径与代理，配置指纹变化后重新查询。
- **下载新一轮布局与已发布布局**：下载文件记录已发布相对路径与完整路径，部分复用期间新文件与旧成片不在同一根时逐文件保留旧位置，未开始新一轮的文件沿任务成片根回退。提交只在 Add 确认后发布保存根：纯新任务确认后即时发布；重下任务逐文件引用切到种子原始布局，成片根由待确认提交根承载，等校验或归档成功才发布。文件服务的路径解析、占用检查、改名日志与归档发布全部按本轮布局与已发布路径表达。
- **未确认 Add 根台账**：Add 请求发出前登记保存根台账；明确拒绝只撤销本次请求的根，结果未知持续占用；同根补发被拒不能否定更早的未知请求，校验意图随被否定请求一并作废。曾完成任务重下时旧成片证据补充为自身复用候选，占用检查纳入待确认根。
- **区分查无与无效响应**：qBittorrent 会话在 HTTP 层捕获 `torrents/info` 原始正文，JSON `null` 不再被归并为空列表，翻译为查询未知；空数组才是成功查无。缺种巡检与预览核对的结论因此可信。
- **动画页排序**：支持按名称、播出日期和种子添加时间排序。
- **出站请求标识**：默认 User-Agent 更新为 `Banori/0.4.0`，已有的顶层 `UserAgent` 自定义配置仍可覆盖默认值。

## v0.2.0

本版本重点完善下载与整理链路：从下载前的文件选择，到单集与合集之间的逐集择优、已有数据复用校验，再到归档恢复和冗余种子清理。同时补充公网部署的认证与反向代理防护，容器构建增加 ARM64 支持。

### ✨ 新增与改进

- **下载前准备**：新增种子先以停止状态加入 qBittorrent，确认文件选择和命名计划生效后再启动下载；准备过程可在重启或请求中断后继续推进。人工暂停与系统准备暂停分别记录，后台对账不会自动恢复人工暂停的任务。
- **文件选择与进度**：同集落选版本及被其他任务承接的正片、随行字幕可取消下载，进度按所选内容计算；完成判定还会核对计划中的选中文件，避免下载器临时改变选择后提前判定整包完成。
- **跨包逐集择优**：单集与合集按每集分别比较版本和筛选优先级。同一个合集可以只下载其中胜出的集数，其余集数继续由其他任务承担，无需整包替换。分别记录当前可播放版本与待完成的新版本，新版本完成后再切换现任。
- **承接与删除回退**：记录每集由哪个任务接替；删除承接方时，按剩余任务的逐集关系恢复旧任务的下载职责或版本引用，修复多级承接、多个任务分别接替一个旧任务时的回退。
- **已有数据复用与交叉做种**：统一已有文件复用和旧版本替换流程，通过 qBittorrent 重新校验候选数据。确认可复用的文件继续使用原数据，其余文件继续下载；不能确认复用时，保留原文件并转入任务专属目录独立下载。
- **校验与归档恢复**：持久化校验轮次、文件映射、结果和未完成的文件操作，重启后重新核对下载器状态；路径、大小或文件选择变化后，旧校验结果失效，避免继续使用不适用的复用依据。
- **归档核对入口**：下载列表展示路径占用、共享布局等归档受阻原因，并提供「重新核对归档」按钮；处理冲突后可以重新尝试整理。
- **包含关系承接**：大包覆盖小包全部承担内容且包含额外内容时，可在已有内容校验通过后逐集承接，无需等待大包所有新集下载完成。内容集合相等时沿用现任；仍有独有字幕或未覆盖内容时保留相应任务。
- **冗余种子清理**：旧任务不再承担任何内容、没有版本引用、人工固定资源或未完成文件操作时，自动从 qBittorrent 移除其种子并保留磁盘文件，数据库保留历史记录。已完成旧任务也参与此检查；未被 Banori 接管或保存路径不匹配的同哈希种子不会因此被移除。
- **双架构容器构建**：发布工作流配置为同时构建 `linux/amd64` 与 `linux/arm64` 镜像，供 x86-64 与 ARM64 主机使用同一镜像标签。

### 🔐 认证与反向代理

- 认证入口按客户端 IP 共用每分钟 5 次提交额度，涵盖密码、双重验证、恢复码和通行密钥请求；超额返回 `429` 与 `Retry-After`，密码登录失败同时计入账号锁定。
- 密码策略改为至少 8 位并拒绝常见泄露密码，不再强制大小写、数字和符号组合；已有账号不会因此重置密码。
- Cookie 与活跃 Blazor 连接统一每 10 分钟重新验证安全戳，缩短改密后旧会话继续有效的时间。
- 通过 `ReverseProxy:KnownProxies` 显式信任代理，处理其转发的客户端 IP 与 HTTPS 信息；默认忽略未配置来源的转发头。
- qBittorrent 钩子新增 POST 调用，可通过 `X-Hook-Token` 请求头传递令牌，减少令牌出现在代理访问日志中的机会；保留旧 GET 调用，并对钩子请求单独限流，轮询对账继续兜底。

### 🐛 修复

- 设置页按卡片独立保存与校验，保存 qBittorrent、Telegram 或 Gotify 任一卡片不再写入其他卡片的草稿，也不会被其他卡片的错误输入阻止。密钥留空仍沿用已保存值，保存后仅清空当前卡片的密钥输入框。
- 下载任务完成或被新任务顶替后，不再继续显示「完成后将替换」提示；失败或丢失且仍可重试的任务保留提示。
- 多文件种子按整个文件集判定集数，修复使用首个可解析文件给整个合集登记单集身份的问题；包内同集多版本复用择优规则，避免争用同一归档名。
- 接管已有种子时，将原始元数据与 qBittorrent 当前文件路径关联；即使文件已经改名，分类和命名模板仍使用原始文件名，并按配置的动画目录整理。
- 修复部分下载归档时处理未选中文件、关联字幕迁让及逐集版本守卫不一致的问题，减少错误替换与路径冲突。
- 修复动画页展开面板被海报遮盖、宽度超过格子及右侧越界的问题。

### 🔧 调整

- 出站请求的 User-Agent 统一为顶层 `UserAgent` 配置，由 Bangumi、RSS 和种子下载客户端共用；默认版本标识更新为 `Banori/0.2.0`。
- 种子文件列表、信息哈希、显示名和 tracker 改由 MonoTorrent 读取；文件核对与改名恢复不再假定解析库的列表位置等于 qBittorrent 文件编号，并适配根目录、padding 文件及空文件的编号差异。
- SQLite 与 MySQL 均新增下载准备与文件选择、逐集版本登记、数据校验与归档恢复状态的数据库迁移。
- 更新日志统一使用中文，保留历史版本的中文记录。

### ⚠️ 升级说明

- 升级前停止旧实例并备份数据库及配套 `keys/`，MySQL 部署同样需要备份数据库和本地密钥。新版本启动时自动执行数据库迁移，不要让旧版与新版同时写同一数据库；需要回退时应恢复升级前的数据库和配套密钥。
