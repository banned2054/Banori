## v0.2.1

本补丁修复 Nginx 等反向代理后的 HTTPS 登录跳转，并统一种子来源标签、命名与同源分组的识别规则。

### 🐛 修复与改进

- **反向代理登录**：修复已配置信任代理、转发 HTTPS 信息后，访问受保护页面仍跳转到 HTTP 登录地址的问题；登录跳转正确保留 HTTPS、主机名和端口，未受信任的代理仍不能通过转发头改变协议判断。
- **种子来源识别**：订阅和一次性 RSS 按 RSS 地址识别蜜柑（`mikan`）或 AniBT（`anibt`），不再被种子内的公共 tracker 覆盖。修复将加密订阅地址误当作来源、导致 `{source}` 出现乱码的问题，让 qB 来源 tag、`{source}`、`{site.source}` 和同源分组使用一致的来源。
- **上传种子分类**：仅单独上传 `.torrent` 时按 tracker 识别 `u2`、`byrbt`、`tjupt`，未命中统一归 `bt`，移除手填来源入口。匹配忽略 `passkey`、`secure` 等查询参数，北洋园两个 tracker 归为同组；同时命中不同站点分类时拒绝登记。历史 `U2` 标签与新 `u2` 标签仍按同源参与择优。

### ⚠️ 升级说明

- 反向代理部署仍须配置可信代理，并转发正确的 HTTPS 信息；配置方式见 [README](../README.md#https-反向代理与登录限流)。
- 不会批量重写已有任务或 qB 种子的名称与标签。旧订阅条目缺少有效命名要素时，会提示先重新评估，再创建下载任务，避免继续沿用错误名称。

## v0.2.0

本版本重点完善下载与整理链路：从下载前的文件选择，到单集与合集之间的逐集择优、已有数据复用校验，再到归档恢复和冗余种子清理。同时补充公网部署的认证与反向代理防护，容器构建增加 ARM64 支持。

### ✨ 新增与改进

- **下载前准备**：新增种子先以停止状态加入 qBittorrent，确认文件选择和命名计划生效后再启动下载；准备过程可在重启或请求中断后继续推进。人工暂停与系统准备暂停分别记录，后台对账不会自动恢复人工暂停的任务。
- **文件选择与进度**：同集落选版本及被其他任务承接的正片、随行字幕可取消下载，进度按所选内容计算；完成判定还会核对计划中的选中文件，避免下载器临时改变选择后提前判定整包完成。
- **跨包逐集择优**：单集与合集按每集分别比较版本和筛选优先级。同一个合集可以只下载其中胜出的集数，其余集数继续由其他任务承担，无需整包替换。分别记录当前可播放版本与待完成的新版本，新版本完成后再切换现任。
- **承接与删除回退**：记录每集由哪个任务接替；删除承接方时，按剩余任务的逐集关系恢复旧任务的下载职责或版本引用，修复多级承接、多个任务分别接替一个旧任务时的回退。
- **已有数据复用与交叉做种**：统一已有文件复用和旧版本替换流程，通过 qBittorrent 重新校验候选数据。确认可复用的文件继续使用原数据，其余文件继续下载；不能确认复用时，保留原文件并转入任务专属目录独立下载。
- **校验与归档恢复**：持久化校验轮次、文件映射、结果和未完成的文件操作，重启后重新核对下载器状态；路径、大小或文件选择变化后，旧校验结果失效，避免继续使用不适用的复用依据。
- **归档核对入口**：下载列表展示路径占用、共享布局等归档受阻原因，并提供「重新核对归档」按钮；处理冲突后可以重新尝试整理。
- **包含关系承接**：大包覆盖小包全部承担内容且包含额外内容时，可在已有内容校验通过后逐集承接，无需等待大包所有新集下载完成。内容集合相等时沿用现任；仍有独有字幕或未覆盖内容时保留相应任务。
- **冗余种子清理**：旧任务不再承担任何内容、没有版本引用、人工固定资源或未完成文件操作时，自动从 qBittorrent 移除其种子并保留磁盘文件，数据库保留历史记录。已完成旧任务也参与此检查；未被 Banori 接管或保存路径不匹配的同哈希种子不会因此被移除。
- **双架构容器构建**：发布工作流配置为同时构建 `linux/amd64` 与 `linux/arm64` 镜像，供 x86-64 与 ARM64 主机使用同一镜像标签。

### 🔐 认证与反向代理

- 认证入口按客户端 IP 共用每分钟 5 次提交额度，涵盖密码、双重验证、恢复码和通行密钥请求；超额返回 `429` 与 `Retry-After`，密码登录失败同时计入账号锁定。
- 密码策略改为至少 8 位并拒绝常见泄露密码，不再强制大小写、数字和符号组合；已有账号不会因此重置密码。
- Cookie 与活跃 Blazor 连接统一每 10 分钟重新验证安全戳，缩短改密后旧会话继续有效的时间。
- 通过 `ReverseProxy:KnownProxies` 显式信任代理，处理其转发的客户端 IP 与 HTTPS 信息；默认忽略未配置来源的转发头。
- qBittorrent 钩子新增 POST 调用，可通过 `X-Hook-Token` 请求头传递令牌，减少令牌出现在代理访问日志中的机会；保留旧 GET 调用，并对钩子请求单独限流，轮询对账继续兜底。

### 🐛 修复

- 设置页按卡片独立保存与校验，保存 qBittorrent、Telegram 或 Gotify 任一卡片不再写入其他卡片的草稿，也不会被其他卡片的错误输入阻止。密钥留空仍沿用已保存值，保存后仅清空当前卡片的密钥输入框。
- 下载任务完成或被新任务顶替后，不再继续显示「完成后将替换」提示；失败或丢失且仍可重试的任务保留提示。
- 多文件种子按整个文件集判定集数，修复使用首个可解析文件给整个合集登记单集身份的问题；包内同集多版本复用择优规则，避免争用同一归档名。
- 接管已有种子时，将原始元数据与 qBittorrent 当前文件路径关联；即使文件已经改名，分类和命名模板仍使用原始文件名，并按配置的动画目录整理。
- 修复部分下载归档时处理未选中文件、关联字幕迁让及逐集版本守卫不一致的问题，减少错误替换与路径冲突。
- 修复动画页展开面板被海报遮盖、宽度超过格子及右侧越界的问题。

### 🔧 调整

- 出站请求的 User-Agent 统一为顶层 `UserAgent` 配置，由 Bangumi、RSS 和种子下载客户端共用；默认版本标识更新为 `Banori/0.2.0`。
- 种子文件列表、信息哈希、显示名和 tracker 改由 MonoTorrent 读取；文件核对与改名恢复不再假定解析库的列表位置等于 qBittorrent 文件编号，并适配根目录、padding 文件及空文件的编号差异。
- SQLite 与 MySQL 均新增下载准备与文件选择、逐集版本登记、数据校验与归档恢复状态的数据库迁移。
- 更新日志统一使用中文，保留历史版本的中文记录。

### ⚠️ 升级说明

- 升级前停止旧实例并备份数据库及配套 `keys/`，MySQL 部署同样需要备份数据库和本地密钥。新版本启动时自动执行数据库迁移，不要让旧版与新版同时写同一数据库；需要回退时应恢复升级前的数据库和配套密钥。
- 自定义过 `Bangumi:UserAgent` 或环境变量 `Bangumi__UserAgent` 的部署须改用顶层 `UserAgent`，旧键不再读取。
- 反向代理部署须配置 `ReverseProxy__KnownProxies__0` 等可信代理地址；否则转发头会被忽略，用户可能共用代理 IP 的登录限流额度。具体配置见 [README](../README.md#https-反向代理与登录限流)。
- 旧版「已完成种子保留」不再是冗余清理的豁免条件：当全部内容职责被其他任务接替且无其他保留条件时，旧种子会自动从下载器移除，磁盘文件保留。
- 数据复用需要 Banori 与 qBittorrent 对下载文件使用一致的路径映射；同名、同大小或解析结果一致都不代表内容相同，须以目标种子的校验结果确认。无法确认时可能转为独立下载。

## v0.1.2

本补丁修复 Docker 发布遗漏 Blazor 脚本的问题，并调整运行数据目录和首位管理员配置。已有部署在更新容器前，请先阅读下方升级说明。

### 🐛 修复

- Docker 发布在复制完整 Razor 源码后重新还原依赖，确保镜像包含 Blazor 框架脚本及静态资源路由，修复发布容器因脚本缺失而无法正常交互保存设置的问题。
- 旧运行数据的忽略规则收窄到数据库文件和 `keys/`，避免 Windows 大小写不敏感时误忽略源码 `Data/`。新增 `config/` 运行目录的 Git 和 Docker 构建排除规则。

### 🔧 调整

- 默认 SQLite 数据库改为 `config/banori.db`，Data Protection 密钥改为 `config/keys/`（Docker 内为 `/app/config`），与源码 `Data/` 分离。
- Compose 默认使用 `./config:/app/config` 目录映射，不再默认使用命名卷；同步目录创建、属主修正、启动诊断和备份文档。
- 检测到旧 `data/` 或 `App_Data/` 数据且新位置缺少默认数据库或密钥文件时停止启动。此检查用于防止遗漏迁移，不会自动迁移，也不代表完整的数据一致性校验。
- 首位管理员配置键统一改为 `BANORI_USERNAME`、`BANORI_PASSWORD`，同步应用、Compose 和开发配置。旧 `Username`/`Password` 键不再读取，已有账号不受影响。
- 新增数据路径迁移检查和管理员配置回归测试，并修正 GitHub Actions 发布触发方式的文档说明。

### ⚠️ 升级说明

- 先备份并停止旧应用。已有目录映射将 `./data:/app/data` 改为 `./data:/app/config`，保留宿主机目录及内容；新部署默认使用 `./config:/app/config`。
- 已有命名卷部署应保留 `banori-data` 及顶层卷声明，仅将容器目标改为 `/app/config`；若要切换目录映射，须先将卷内数据复制到宿主机目录。不要改用新空目录或删除原卷。
- 本地运行须将数据库及配套文件、`keys/` 一起复制到 `Banori/config/`；不要整体移动或删除 Windows 的源码 `Banori/Data/`。MySQL 部署也必须保留本地密钥。
- 旧管理员环境变量或 User Secrets 键须改为 `BANORI_USERNAME`、`BANORI_PASSWORD`。已有 Compose `.env` 若已使用这些名称，无需改名，但自定义容器环境变量映射须同步更新。这些配置不会重置已有账号。

## v0.1.1

本补丁版本修复 v0.1.0 发布后发现的问题，并改善默认日志输出与 Docker 启动诊断。

### 🐛 修复与改进

- 生产和开发环境默认不再输出 EF Core 执行成功的 SQL 日志，仍保留数据库命令警告和错误，减少日志刷屏；应用日志默认等级仍为 `Information`。
- 支持通过环境变量开启应用 `Debug` 日志或按需启用 SQL 诊断。入口脚本改用 Bash，确保名称中带点的日志类别环境变量能够正确传递。
- 修复 Docker 数据目录权限处理：入口脚本按 `PUID`/`PGID`（默认 `1654:1654`）设置 `/app/data` 属主，并以对应身份运行应用。启动时增加目录可写性检查，失败时输出当前进程身份和修复建议。
- 补充 bind mount、命名卷权限行为、NAS 配置，以及 NFS root-squash 和 NAS ACL 等存储限制说明。

## v0.1.0

这是 Banori 的首个版本，一个面向个人或家庭媒体库的动漫 RSS 管理面板，基于 .NET 10 与 Blazor 构建。「订阅 → 评估 → 下载 → 整理」核心链路可供日常使用；界面与配置仍会随需求演进。

### ✨ 新增与改进

- 管理 Mikan、AniBT 动漫 RSS 订阅：定时刷新、去重入库，RSS 地址加密保存。
- 条目评估：解析条目信息、关联 Bangumi 条目、同集择优，并展示筛选理由与命名预览。
- 下载管理：将 RSS 链接或本地上传的种子提交到 qBittorrent，跟踪任务状态，接管 qBittorrent 存量种子；支持 qBittorrent 钩子即时对账，轮询兜底。
- 下载完成后的整理归档：种子名与文件名模板分离，并提供来源明确的命名变量；附属文件移入 `Seed/`，被新版本顶替的文件进入 `.replaced` 备份目录而非直接删除。
- 动画总览页按下载任务聚合，每集只显示现任版本，并提供单集下探面板。
- 通知投递：支持 Telegram 与 Gotify 渠道，同事务入队、渠道独立重试，并提供投递记录页。
- 设置页统一管理命名代理，覆盖订阅、qBittorrent、Telegram 与 Gotify 全链路。
- 通过环境变量引导首位管理员，登录页支持用户名登录。
- 数据库默认 SQLite，可选 MySQL，共用同一 EF Core 模型。
- 提供 Docker 部署与持久化数据卷，镜像发布到 GHCR。

### ⚠️ 平台与已知限制

- 发布形态为 GHCR 容器镜像（具体发布触发方式见 README）；不提供安装器、独立二进制或自动更新。
- 下载整理需要 qBittorrent，且 Banori 与 qBittorrent 必须以一致的方式挂载下载路径。
- 本版本界面仅提供简体中文。
- 项目仍处于早期开发阶段，界面、配置方式和数据布局在版本间可能变化。
- 从早期本地运行迁移数据需要手动将 `App_Data` 复制进 Docker 卷，操作步骤与备份说明见 README。
