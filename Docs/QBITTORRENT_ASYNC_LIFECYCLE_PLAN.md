# qBittorrent 异步准备、校验与完成确认改造计划

日期：2026 年 10 月 20 日。

状态：设计与实施计划。2026-10-20 第一阶段基础改动通过 812 项源码测试后，复审发现共享写入风险、完整任务多余启动及 ReadyToRun 丢响应恢复三个缺口，现已补充修复与回归；同日第二阶段（时间策略、可恢复等待与调度）已实施，两轮审查共发现 10 个可复现问题（含 2 个共享数据保护缺口）并已全部修复回归，全量 844 项测试通过，见两个阶段各自的实施记录。第三、第四阶段尚未实施，真实 qB 验收未做。本文其余描述除已标注的实施记录外，仍为拟议设计而非现有行为。

本文补充 [Torrent 文件选择与已有数据复用设计](TORRENT_DOWNLOAD_DESIGN.md)，专门处理添加、文件选择、改名、移动、recheck、暂停、启动及完成归档之间的异步时序。原设计的产品规则继续有效；本文描述的阶段、字段和默认时间均是拟议实现，不是现有 API。

## 目标与范围

核心原则：**请求已接收、操作已执行、查询结果已更新，是三个不同的时间点。按阶段等待证据，不要求 qB 状态按固定序列出现。**

必须覆盖这些实际情况：

- 刚添加的任务暂时查不到，随后才出现文件清单。
- 改名或移动请求成功后，查询仍短暂返回旧路径。
- recheck 请求后先返回停止，随后才进入校验；也可能校验很快，轮询没捕获 Checking。
- 校验结束后可能停止、下载、排队或做种；分享率达标自动停止是合法行为。
- 停止状态、总进度、逐文件进度可能分批更新，不能组合不同时刻的结果立即作出结论。
- 应用重启、网络超时、请求响应丢失和人工操作发生在任一阶段。

保留原设计三条分支：

1. 已有所需数据：同 hash 接管；其他候选经映射和本轮校验后复用。
2. 没有数据且没有待替换版本：直接在正式目标路径下载，先完成文件选择与命名。
3. 没有数据但存在待替换版本：在 `.tasks/{taskId}` 暂存，完成后走统一归档替换。

不将所有任务改为暂存下载，不增加日常完成的人工审批，不改变跨来源择优边界，不调整分享率或强制做种，不操作真实服务、不修补业务数据库、不提交、不发布。校验失败后的隔离仍是原流程的恢复步骤。

### 尚未确定的问题

第 2 集在没有已知旧版的情况下进入 `.tasks`，尚无运行时根因。可能涉及替换关系、复用失败隔离、同 hash 接管或历史部署行为，不能仅凭目录认定具体分支。

## 状态模型与不变量

### 分开记录三个维度

1. **业务意图**：是否允许自动运行、是否人工暂停、当前文件选择和目标布局。
2. **工作阶段**：正在等待添加、布局、校验启动、校验结束、结果稳定、暂停确认、启动确认或归档。
3. **下载器观察**：原始状态、停止/校验/移动属性、总进度、逐文件结果、观察时间。

不使用单个 `IsSystemPaused` 同时表达业务意图、实际暂停状态和界面阶段。保留现有任务生命周期；是否需要扩展枚举由实施时按最小迁移决定，不新增一套平行任务系统。

状态映射须保留原始 qB 状态供解释：`StoppedUpload` 和 `StoppedDownload` 都属于停止；完成程度独立判定。Checking 三类均可识别；Moving、排队、错误和未知状态不能简单当成正在下载。先审计映射调用方，再调整共享类别，避免影响普通完成、人工暂停和接管分支。

### 不变量

- 副作用前持久化意图，响应成功后仍等待可验证后置条件。
- 同一任务每阶段只有一个尚待确认的请求；旧响应不能覆盖新轮次或人工操作。
- 校验证据绑定 hash、本轮请求、保存根、逐文件 index/path/size/selection 及布局版本。
- 用户暂停意图独立保存，系统重试和校验收尾不能清除它。
- 观察到停止不等于校验完成；观察到 100% 不等于本轮校验执行过。
- 短暂旧快照、漏采状态与网络不可达是“未确认”，不自动认定文件损坏或允许共享写入。
- 在复用尚未证实的共享路径上不主动 Resume、不重命名迁移旧成片、不允许补下缺失数据。
- 全部所选文件已经证实完整后，分享率达标停止不阻止完成归档，也不反复 Resume 绕过用户限制。
- `.tasks` 只由明确替换关系或隔离恢复产生，决策必须可追溯。

## 阶段与推进条件

各阶段复用现有 `DownloadService`、`DownloadFileService`、协调门和操作日志。阶段名称为建议，不要求按表逐个新增公开类型。

| 阶段 | 进入动作 | 推进条件 | 等待期间行为 |
| --- | --- | --- | --- |
| 等待添加确认 | 按 hash 先查，必要时停止添加 | hash 可见，保存根和身份清单可核对 | 短暂缺失继续查，不重复添加，不标 Lost |
| 等待布局确认 | 确认停止，应用选择、改名及必要移动 | 文件 index/size/selection/path 与计划一致，移动结束 | 旧路径保留日志；先查后决定是否补发，禁止每轮重发 |
| 等待校验开始 | 持久化轮次与布局快照，发送一次 recheck | 本轮可归属的 Checking 证据出现 | 立即开始观察；旧停止态和旧进度不视为完成 |
| 校验中 | 保留本轮 Checking 与进度观察 | 退出校验和移动状态 | 不把 Checking 当暂停失败，不重复 recheck，不拿校验进度判文件完整 |
| 等待结果稳定 | 记录退出校验的时间和首个结果样本 | 跨刷新间隔核对结果一致，映射和文件身份不变 | 暂停、下载、做种、排队分别处理；暂时低进度继续观察 |
| 等待停止确认 | 需要保护未证实的共享数据或执行文件操作时请求停止 | 已停止且满足结果稳定条件 | 按请求确认期限等待，不按查询次数扣重试预算 |
| 完成确认或补下 | 本轮证据和文件结果通过 | 所选文件全部完整则统一归档；允许写入的独立缺集才启动 | 无须经过网络“下载中”；保留人工暂停与分享限制 |
| 等待启动确认 | 仅对确需继续下载或现有产品行为允许的运行发出 Resume | 合法运行态，或文件完整且因限制停止 | 后一种情况不能再次认定 Resume 失败；不得循环启动 |
| 归档确认 | 复用现有迁让、移动与逐集切换 | 实际布局和引用关系确认 | 失败保持可恢复日志，不把数据完整性与整理失败混为一谈 |

### recheck 请求与本轮归属

发送前清空本轮观察与稳定样本，记录布局版本和请求时间。网络超时表示结果未知，应先观察再决定是否补发；不能把旧轮 Checking、上次 100% 或任意 `rid` 当成本轮证据。

轮询从请求后立即开始，**最短观察时间限制何时下结论，不限制何时开始采样**。不能先固定睡几秒再开始查询，否则可能主动错过快速校验。

未捕获 Checking 的快速任务没有现成的可靠完成凭证：

1. 在启动确认窗口内持续快速观察，不因非 Checking 立即结束。
2. 无移动、无活跃校验、可安全确认停止后，允许有界补发一次，并重置本轮证据。
3. 仍无法归属到本轮时保留“校验执行未确认”及原因，不写 `ReusedVerified`。
4. 不凭重复 100% 证明校验执行，也不因漏采 Checking 直接断言数据损坏、删除数据或自动重新下载。需重新核验的任务暂停自动推进，沿用可解释的失败/重试入口；这只针对证据异常，不是普通任务的审批步骤。

未来若引入可靠的校验完成事件，必须验证版本支持、hash/轮次归属与事件丢失恢复，才可作为 Checking 观察的替代。`sync/maindata` 是快照增量，不是完整事件日志。

### 校验后状态与共享数据保护

| 观察结果 | 处理 |
| --- | --- |
| `StoppedUpload` / `StoppedDownload` | 正常停止结果；进入稳定观察，不发多余暂停，不单凭名称决定完整性 |
| Checking | 继续本轮校验，不暂停正常校验，不执行布局操作 |
| Moving | 等待移动结束；目标改变或映射失效则作废本轮证据，不把移动算 Checking |
| 下载中或等待下载 | 未证实的共享布局需受控暂停防止补写；独立布局按当前阶段等待，不直接标失败 |
| 做种或等待做种 | 不等于本轮校验已经证实；需要稳定读取或文件操作时先停止确认，完整后允许正常完成 |
| Error / MissingFiles | 先确认是否真实且持续、是否与已有操作相关；紧急共享写入风险先保护，不能靠长宽限期继续运行 |
| Unknown、暂时查不到、请求超时 | 保持未确认，按独立可见性/网络期限等待；不得转换成 0% 或直接补发破坏性操作 |

停止请求成功后不立刻认定生效；仍在校验的正常临时启动不能累计成暂停失败。也不能仅因为 `PauseAttempts > 0` 就作废全部证据或强制隔离：是否作废应由布局变化、真实写入风险及证据归属决定。

暂停不能撤销已经发生的共享写入。如果观察显示未证实数据可能被补写，保留风险与日志、停止推进，不凭后续稳定 100% 消除疑点。需要独立下载时仍走保护原数据的隔离链。

### 稳定结果与完成判定

稳定窗口从退出 Checking/Moving 后开始。分别读取任务状态和逐文件清单，再回读任务状态；这些不是原子快照，必须通过后续间隔采样确认。

- 采样核对根、index、path、size、selection 与布局版本；冲突、人工覆盖或新轮次使当前样本失效。
- 必须有本轮执行证据；等待足够久和多次相同结果不能代替证据。
- 所选文件按逐文件进度确认；Checking 中的总进度仅用于展示。
- 刚退出校验时低于 100% 先等待结果收敛；持续一致且本轮证据成立后，才能确认该映射存在缺失。
- 零字节文件不因零除或 0% 阻塞；未选文件不影响所选内容完成。
- 候选均完整而独立新文件未完成：登记候选复用证据，只启动可安全写入的其余文件。
- 全部选中文件完整：走统一完成与归档，不为了制造“下载中”状态而 Resume。
- 稳定观察期间超时只表示结果无法确认；与“校验确认缺失”“文件身份冲突”“归档受阻”分别记录。

## 时间策略与调度

### 建议初始参数

以下是实现与真实 qB 调优的起点，**不是已验证配置，不是正确性的证据，也不是必须新增的用户设置页**。优先内部统一策略与可测试时间源，后续按日志调整。

| 参数 | 建议起点 | 说明 |
| --- | --- | --- |
| 准备及短确认阶段采样 | 约 1 秒 | 批量读取到期任务，避免任务数乘以无限轮询 |
| 长校验采样 | 约 2 秒 | 与实际 qB 刷新间隔协调，可退避；确保前后阶段更密集 |
| 普通下载空闲对账 | 沿用 15 秒 | 不因少量准备任务让全量下载永久高频查询 |
| 添加可见性、布局生效、校验启动窗口 | 各自约 30 秒 | 三个独立计时，不共享一个截止时间 |
| 最短结果稳定窗口 | 不低于约 5 秒且覆盖多个实际刷新周期 | 至少三个间隔样本；若可知刷新间隔则按更大值计算 |
| 单次停止/启动确认窗口 | 约 15 秒 | 过期后才允许有界补发；轮询不计次数 |
| recheck 补发预算 | 初次加一次有界补发 | 原请求仍可能运行时不可补发；持久化预算 |
| 控制请求重试预算 | 初次加至多两次补发 | 网络结果未知先查询，按时间限制，不能靠 pulse 耗尽预算 |
| 长校验无进展期限 | 初始沿用约 10 分钟，再按实测调整 | 与总校验上限分开；持续有进展不因启动窗口过期失败 |
| 单轮校验总上限 | 初始建议 2 小时，需按大包/慢盘验收 | 不允许进度抖动无限续期；到期也先停止确认再退出自动推进 |

“无进展”只由有意义的校验进展更新，不因重复同样快照、请求成功或网络重试重置。稳定窗口也不能因总进度一直相同而忽略路径或选择变化。

### 执行方式

- 继续使用一个 worker、一套会话入口、一条对账恢复链。查询失败和超时按任务隔离，不能拖死整个队列。
- 持久化下一次可观察时间和各阶段截止时间；一次推进执行有限步骤，然后释放协调门。
- worker 按最早到期任务或 pulse 唤醒；pulse 不能越过最短确认间隔、绕过请求预算或形成忙循环。
- 在协调门内完成必要的重新读取、意图提交与有限副作用；门外等待到期，不持锁 `Task.Delay`。
- 多 scope、人工操作与后台唤醒仍受现有协调门保护；不能为了高频采样取消提交前权威状态检查。
- 初期继续用现有查询端点，先修正确认语义。是否采用 `sync/maindata` 作为快照来源单独评估；如采用，必须正确合并差量、删除项、全量重置和会话重建，并继续单独读取文件结果。

## 持久化、重试与重启恢复

优先扩展已有校验意图和文件操作日志，避免另建重复状态表。字段名称在实施前确定，至少表达：

- 当前阶段、阶段进入时间、当前操作或校验轮次。
- 请求登记/发送时间、最早可判断时间、下一次采样时间、请求确认期限。
- 校验启动、最后有效进展、总截止时间；本轮 Checking 观察证据。
- 布局版本或摘要、最后稳定样本及稳定起始时间、样本数。
- 当前待确认控制请求、实际发出次数、下次允许补发时间。
- 路径决策原因及关联旧任务/文件：正式下载、替换暂存、复用候选、隔离恢复、同 hash 接管。

请求返回前崩溃时不得凭“已登记发送”推定远端已执行。重启先查 hash、根、布局与状态；不能把恢复后第一次停止/100% 直接作为本轮完成证据。

稳定样本遇到重启或无法确认连续观察时重新积累，保留仍有效的轮次与布局证据。数据库持久化使用 UTC；进程内计时与测试统一使用 `TimeProvider`，考虑时钟跳变，不因未来时间戳永久等待。

`ReadyToRun` 是启动意图与已验证结果，不应重走一遍 recheck。必须处理 Resume 已执行而响应/落库丢失、Resume 后立即因分享限制停止等情况，防止将自身合法启动判为外部运行。

人工重试按原因选择“继续确认”“重新发起校验”“恢复布局”“隔离恢复”，不能统一清除所有日志、重置所有次数或直接 Resume。旧 JSON 缺失新字段须有确定恢复规则；需要结构迁移时同时覆盖 SQLite/MySQL，不能静默修改历史成功结论。

## 自动化验收矩阵

使用 `TimeProvider` 和脚本化假会话推进时间，模拟“写请求被接收但读结果尚未改变”。不使用真实睡眠堆叠测试时长，不只测试即时修改内存状态的理想会话。

| 场景/观察序列 | 必须验证 |
| --- | --- |
| 添加响应成功 → 多次查不到 → hash 与文件清单出现 | 窗口内不重加、不标 Lost；身份完整后再布局 |
| 添加响应丢失，但远端已添加 | 按 hash 接管本轮准备，不创建第二个任务 |
| 改名成功 → 旧路径多轮 → 新路径 | 不提前 recheck，不每轮重发，不提前确认日志 |
| 文件选择延迟、移动中路径分步变化 | 等实际后置条件，不拿 Moving 当校验 |
| recheck → StoppedDL → StoppedDL → Checking → StoppedUP | 不把首次停止当校验结束；完整后不误报暂停失败 |
| recheck 后很快 100%，全程未采到 Checking | 不凭旧/新 100% 宣告本轮通过；有界补查后明确未确认 |
| Checking → StoppedUP，但文件进度滞后 0%/部分 → 100% | 稳定窗口前不隔离重下，最终直接完成 |
| Checking → 做种 → 请求停止 → 旧做种快照 → StoppedUP | 等停止确认，不按查询次数耗尽预算，不因暂停本身作废证据 |
| Checking → 下载/排队且候选未完整 | 共享候选不允许补写；独立内容按规则处理 |
| 分享率达标，Resume 后立即 StoppedUP | 不重复 Resume，不误判失败，完整内容完成归档 |
| 校验进度 100%，所选文件仍不完整 | 不把校验百分比当数据完整，不误标完成 |
| 非选中文件缺失、零字节文件、部分候选加独立缺集 | 正确计算所选内容；完整候选不重下，独立缺集可补下 |
| 多次同样低进度，最终本轮稳定证据确认缺失 | 区别“确认缺失”与“未知”，按原隔离链保护旧数据 |
| 暂停请求真正不生效 | 超过确认窗口且预算耗尽才受阻，日志可解释；不继续共享写入 |
| 高频 pulse、并发刷新/人工操作、多个长短任务 | 不忙循环，不重复副作用，不使用过期任务快照覆盖新状态 |
| 在发送前后、Checking 中、稳定观察中、ReadyToRun 和归档中重启 | 从持久意图与远端事实恢复，不跨轮复用证据 |
| 人工暂停/改名/移动/更改选择/删除；网络错误和 Unknown | 尊重人工意图；证据失效有依据；网络错误不变成零进度 |
| 无旧版无候选、存在旧版替换、复用失败隔离 | 分别选择正式路径、替换暂存、隔离路径，原因可追溯 |
| 校验完成但归档受阻 | 保留内容完整信息、旧数据与恢复日志，不显示为数据下载失败 |
