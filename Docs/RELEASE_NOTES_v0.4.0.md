# Banori v0.4.0

本版本围绕种子丢失与下载路径布局更新：后台巡检自动发现种子被删除的旧任务并支持受控重下；下载提交与归档按新一轮布局解析路径，未确认的 Add 请求持续占用提交路径，避免结果未知时并发误写同一目标。

## 主要更新

- **缺种巡检与受控重下**：任务按排期巡检，严格区分「查到」「成功查无」「查询未知」三种结果；首次查无留下待复核证据，第二次查无且下载器配置一致才确认缺失，查询未知不写任何字段。确认缺失的任务进入「丢失」分组并显示徽标，页面提供重新下载入口：种子已回来时只清除标记，确认查无才建立新一轮受控重下，固化已发布布局并清除旧意图与缺种证据；同 hash 活动任务先明确拒绝。巡检配置指纹绑定连接地址、用户名、保存路径与代理，配置指纹变化后重新查询。
- **新一轮下载布局**：下载文件记录已发布成片布局，部分复用期间新文件与旧成片不在同一根时逐文件保留旧位置，未开始新一轮的文件沿任务成片根回退。提交只在 Add 确认后发布保存根：纯新任务确认后即时发布，重下任务等校验或归档成功才发布。文件服务的路径解析、占用检查、改名日志与归档发布按本轮布局与已发布路径表达。
- **未确认 Add 根台账**：Add 请求发出前登记保存根台账；明确拒绝只撤销本次请求的根，结果未知持续占用；同根补发被拒不能否定更早的未知请求，校验意图随被否定请求一并作废。曾完成任务重下时旧成片证据补充为自身复用候选，占用检查纳入待确认根。
- **区分查无与无效响应**：qBittorrent 会话在 HTTP 层捕获 `torrents/info` 原始正文，JSON `null` 不再被归并为空列表，翻译为查询未知；空数组才是成功查无。缺种巡检与预览核对的结论因此可信。
- **动画页排序**：支持按名称、播出日期和种子添加时间排序。
- **出站请求标识**：默认 User-Agent 更新为 `Banori/0.4.0`，已有的顶层 `UserAgent` 自定义配置仍可覆盖默认值。

## 升级注意事项

- 本版为 SQLite 和 MySQL 新增数据库迁移（缺种巡检与清理确认、已发布成片布局、未确认 Add 根台账及待确认提交根），启动时自动应用；存量列均可空、无默认值。升级前请停止旧实例，备份整个 `config/` 目录，MySQL 部署还须单独备份数据库；不要让新旧实例同时写同一数据库。
- 回退时请恢复升级前的数据库和配置备份，不能只切换回旧镜像。
