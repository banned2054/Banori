# P3 安全下载闭环验收

日期：2026-09-26

## 已完成范围

- 新增 `DownloadTask` 实体与 `AddDownloadTasks` 迁移：持久化下载意图、规范化 info-hash（40 位小写十六进制）、种子原始字节、隔离保存路径、命名快照、集数与版本、执行状态、失败步骤和替换关系。同一资源在活动状态（待提交 / 提交结果待确认 / 下载中 / 已暂停）下由数据库部分唯一索引（`IX_DownloadTasks_InfoHash`，含 `Status` 过滤）阻止重复登记。
- 条目详情页可对“已选择”条目创建下载任务：创建时校验决策、下载 .torrent、用 Core 提取器计算 info-hash，登记成功前不访问下载器；同条目或同 hash 的活动任务会被拒绝。
- 下载闭环由 `DownloadService` 实现：提交（临时文件上传，分类固定 `Banori`，保存路径为 `基础路径/Subject/命名快照-hash8` 的隔离子目录）→ 对账（进度、暂停、完成、丢失）→ 完成后按命名快照改名（单文件保留原扩展名）→ 记录替换关系。重试沿用创建时的决策与命名快照。
- 提交结果按 SDK 语义区分：响应 `"Fails."` 或 `BadRequest` 视为确定失败；认证类异常（登录失败 / 401 / 403）标记失败步骤“认证”；服务器 5xx 与网络中断进入“提交结果待确认”，下一轮按 hash 对账后再决定继续或重试（自动重试上限 5 次，达到后如实失败等待人工重试）。
- 人工暂停保留：页面或下载器内的暂停都记录为人工暂停，对账绝不自动恢复；下载器内手动恢复会被对账识别并转回下载中。
- 替换安全：同 Subject + 同集数的新版本任务创建时自动记录 `ReplacesTaskId`；新任务在隔离路径完成并改名后，旧任务才被标记为“已被替换”。旧任务与文件默认保留，清理是后续独立行为。新任务失败不影响旧资源。
- 设置页新增 qBittorrent 下载器卡片：启用开关、地址、账号、密码（Data Protection 加密保存，留空表示不修改）、下载器侧保存路径与连接测试。下载器未启用或未配置时，创建下载意图被拒绝，对账静默跳过。
- 下载任务页面展示任务名、中文状态、进度、时间、失败步骤与错误、替换记录，并提供暂停 / 恢复 / 重试操作；页面每 15 秒限频重新查询持久化状态。总览页新增“进行中下载”计数。
- Banned.Qbittorrent 1.7.0 接入边界：`IQbittorrentSession` / `IQbittorrentSessionFactory` 封装登录、版本协商、Hash 规范化与状态翻译（`QbittorrentTorrentStateMapper`），业务服务不感知 HTTP；会话随用随建随释放，不跨请求共享。

## 关键设计决定

- **info-hash 在提交前提取**：Banned.Qbittorrent 1.7.0 的 `FetchTorrentMetadata` / `ParseTorrentMetadata` 均为下载器服务端接口，SDK 内不含本地 bencode 解析；`TorrentInfoHashExtractor`（Core 纯规则）扫描 bencode 边界取 info 字典做 SHA-1，是“响应丢失按 hash 对账”的前提。
- **POST 副作用不重放**：反编译核验 SDK `NetService.ExecuteWithRetry` —— 超时 / 断连时对可能有副作用的 POST 明确抑制重试并抛 `QbittorrentServerErrorException`，因此“响应丢失 → 本地 Submitting → 按 hash 对账”必须由业务实现，SDK 不兜底。5xx 自动重试（默认 3 次）与认证失败自动重登录由 SDK 完成。
- **`AddTorrent` 返回原始文本**（`"Ok."` / `"Fails."`），解释权在业务服务。
- SQLite 不支持 DateTimeOffset 服务端排序（P2R 已知约束）：候选任务、任务列表、条目最近任务均在取回后内存排序。
- 下载任务不设删除 / 清理操作；替换只记录关系。订阅级联删除会连带删除任务记录，但下载器中的种子与文件不受影响。

  - **提交后重启**：本地 Submitting + 下载器有任务，新服务实例对账确认且零提交；
  - **重复触发**：同 hash 双活动行被数据库唯一索引阻止；
  - **人工暂停保留**：页面暂停后对账不恢复；下载器内手动恢复被识别；
  - **完成改名与安全替换**：单文件保留扩展名；v2 完成后 v1 标记被替换，下载器中两个种子都保留；
  - **新任务失败不影响旧资源**：v2 提交被 `"Fails."` 拒绝后 v1 保持下载中；
  - 任务丢失 → 人工重试 → 重新提交；
  - 下载器报告错误 → 失败步骤“下载器”；
  - 未配置下载器：创建被拒、对账静默跳过。
- 下载器设置：读写往返、密码受保护存储、留空密码沿用原值、非法地址与启用缺路径校验、连接测试成功与失败路径。
